# Modern compression: implementation and integration contract

This fork keeps two capabilities separate: Apple's **buffer codec API** and a
**native decmpfs file writer**. Only the latter preserves ordinary APFS paths
with kernel-transparent reads. Neither a successful buffer benchmark nor an
accepted private API request establishes native filesystem support.

## Implemented surfaces

| Codec | Apple buffer API in this fork | Native writer |
| --- | --- | --- |
| ZLIB | macOS 10.11+ | Existing types 3/4 |
| LZVN | No public buffer selector | Existing types 7/8 |
| LZFSE | macOS 10.11+ | Existing types 11/12; default |
| LZBitmap | macOS 12+ | Experimental types 13/14, build feature `lzbitmap` |
| LZMESH | macOS 27.0+ | Unavailable: no verified type/framing mapping |
| LZRAVEN | macOS 27.0+ | Unavailable: no verified type/framing mapping |

OS availability is read from `kern.osproductversion`, not inferred from an SDK
or scratch-buffer size. A generated byte-for-byte round trip verifies actual
buffer availability. A zero scratch size is legal. Decode helpers allocate an
extra byte because Apple's decoder can return the destination size on truncated
output. Empty and over-limit allocating requests fail explicitly.

The existing default compressors remain unchanged. Native LZBitmap requires an
explicit build feature and successful runtime self-test. It shares the existing
64 KiB little-endian resource-fork offset table, uses a 0xff raw-block marker,
and forces verification before atomic replacement in both the CLI and library.
Recognition of types 13/14 remains available when encoding is disabled.

## Capability contract, version 1

```sh
applesauce capabilities --json
applesauce capabilities --json --require-native lzraven
```

The second command currently exits **1**, after printing the report, because
native Raven compression is unavailable. Companion tools must treat nonzero
exit as refusal, including old binaries that do not recognize the command.
There is no silent algorithm/backend fallback.

The JSON has `schema_version: 1`, `applesauce_version`, `host` (OS, architecture,
macOS product version and build), and `codecs`. Each codec has:

```json
{
  "name": "lzraven",
  "apple_buffer": {
    "available": true,
    "verified_roundtrip": true,
    "reason": "generated buffer round trip passed; this does not establish native filesystem support"
  },
  "native_decmpfs": {
    "writable": false,
    "decmpfs_types": [],
    "experimental": true,
    "reason": "no verified native decmpfs type/framing mapping; buffer support does not authorize file compression"
  }
}
```

This is an illustrative macOS 27 result, not a claim about the current reader's
host. Codec names are lowercase. Explanatory strings are not stable API fields.
`writable` means the writer is enabled in this binary and on this host; volume,
file eligibility and achieved savings still need checks during compression.
Known types can be reported while `writable` is false. An empty type list can
never grant native permission. `--require-native` evaluates only the native
writer contract, never `apple_buffer.available`.

The sessions frontend calls the exact attesting command for explicitly selected
LZRAVEN, LZMESH and LZBitmap before scanning or mutating anything. Legacy defaults
continue working with upstream Applesauce. Restore does not need an available
encoder. See [sessions integration](https://github.com/chriscoveriesorg/compress-agent-sessions/blob/main/docs/experimental-lzraven.md).

## Read-only benchmarks

```sh
applesauce benchmark-codecs --json
applesauce benchmark-codecs --codec lzfse,lzmesh,lzraven --file /path/to/STABLE-COPY.jsonl --json
```

Default inputs are generated JSONL and deterministic high-entropy bytes. An
explicit file must be regular, nonempty, at most 64 MiB, and unchanged during
the read; final-component symlinks are refused. Reads remain bounded if it grows.
No source text or path is included in the JSON, and nothing is uploaded.

Each selected codec is measured as a whole buffer and as independent 64 KiB
buffers. The latter models dictionary resets, **not** a valid Raven/Mesh APFS
format. Encoded bytes exclude decmpfs/resource-fork overhead, filesystem block
allocation and raw-block policy. Three trials run by default (`--iterations
1..10`); times include buffer allocation and API-managed scratch. Every trial
checks exact decoded length and bytes. Actual disk savings, kernel random-read
latency, and real-log workload selection are separate release qualifications.

## CI and the manual probe button

The [workflow](../.github/workflows/modern-compression-probe.yml) automatically
runs safe buffer/contract tests on relevant PRs and pushes, using GitHub's
hosted `xcode-27` label. It compiles the Swift reference probe and private C
helper, but never executes the private helper on an automatic event. JSON,
TSV, logs and exact environment records are retained as workflow artifacts.

The **Run workflow** button leaves `probe_filesystem` and `probe_candidates`
off by default. The runner image published during this work is macOS 27.0.1;
buffer APIs are valid there, while our private trial policy requires 27.2+.
27.2 is a safety gate, **not evidence of Raven/Mesh APFS support**.

On a backed-up macOS 27.2+ test Mac:

```sh
bash hack/run-local-apfs-probe.sh              # known controls only
bash hack/run-local-apfs-probe.sh --candidates # extra explicit requests, after controls pass
```

The script requires typed confirmation, creates a fresh disposable APFS image,
requests established controls 12/14, detaches it completely, then reattaches
read-only for exact logical readback and metadata checks. Only after those
controls pass can a separate image receive additional type requests 15–22.
The actual stored type, UF_COMPRESSED flag, allocation and readback are reported.
A queue may accept an unsupported request and store a different codec. Types
15/16 are independently documented as Apple framed LZ4 on macOS 27, **not**
Raven/Mesh. A matching type is still not codec identification.

Images and logs are retained for inspection. Generated image data is not
uploaded by CI. The helper refuses an unmarked/non-APFS/non-root mount and
requires a read-only mount for its verification phase. Never target personal
files or a live data volume. An isolated image protects file selection but
cannot isolate a filesystem decoder running in the **host kernel**; a kernel
hang or panic remains possible.

## Family integration and remaining gate

- [Applesauce fork](https://github.com/chriscoveriesorg/applesauce): codec implementation, native framing, diagnostics and verification.
- [compress-agent-sessions fork](https://github.com/chriscoveriesorg/compress-agent-sessions): cold-file eligibility, dry runs, scheduling and restore policy.
- [ZGX](https://github.com/chriscoveriesorg/zgx) and [integration issue #504](https://github.com/chriscoveriesorg/zgx/issues/504) (private): unchanged logical content, hit paths, byte spans and snippets. Physical metadata or cache receipts can change; compare stable search outputs, not entire timing receipts. Native APFS needs no ZGX codec decoder. Any FSKit fallback must use the explicit logical mount root.
- [Foldy](https://github.com/chriscoveries/foldy) (private): filesystem indexing and space reporting. No automatic installation or linking is implied.

The [roadmap](roadmap-lzraven.md) defines the native GO test and the separate
FSKit-mounted fallback. Do not assign public algorithm selectors to decmpfs,
claim a private queue's admission boolean means success, or enable a writer
based on a cached immediate read alone.

## Evidence

- [Apple LZRAVEN](https://developer.apple.com/documentation/compression/compression_lzraven) and [LZMESH](https://developer.apple.com/documentation/compression/compression_lzmesh): public buffer APIs and availability.
- [Apple-authored SDK header](https://github.com/xybp888/iOS-SDKs/blob/4a48e5409f8ea6ac422c44d91b86fa0f8ae010ff/iPhoneOS27.2.sdk/usr/include/compression.h): selectors 0x702, 0xD05 and 0xE05; zero scratch and truncated decode semantics. This is a third-party mirror of Apple's header.
- [XNU decmpfs](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/decmpfs.c): registered filesystem decompressor lookup.
- [Siguza/fscmp](https://github.com/Siguza/fscmp): private queue API and named LZBitmap 13/14 types.
- [go-apfs-v2 native compression qualification](https://github.com/deploymenttheory/go-apfs-v2/blob/main/docs/compression-writer.md): independent format/readback evidence, queue fallback, LZ4 15/16 qualification. Its claims are evidence from that project, not a substitute for our own tests.
- [apfs-probes](https://github.com/gregordinary/apfs-probes): independent codec/type/layout investigation methodology, not proof of Raven/Mesh support.
- [Official runner image](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md): exact hosted OS/build; always use the recorded run environment for results.
